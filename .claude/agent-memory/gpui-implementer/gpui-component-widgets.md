Verified by compiling vault-app P2.5 (see [[gpui-api-facts]], [[gpui-version-pins]]).

- Input: `gpui_component::input::{Input, InputState, InputEvent}`. `InputState` is `gpui_base::input::InputBaseState<InputMode>`, source in `gpui-base-0.8.1/src/input/base/state.rs`. Build: `cx.new(|cx| InputState::new(window, cx).masked(true).placeholder("..."))`. Read: `state.read(cx).text()` -> `&Rope` (`.to_string()`, `.len()`); `.value()` -> SharedString (avoid for secrets). Write: `set_value(impl Into<InputContent> /* &str, String */, window, cx)`, `focus(window, cx)`. Events: `InputEvent::{Change, PressEnter { secondary, shift }, Focus, Blur}` via `cx.subscribe_in`. Element: `Input::new(&state)` with `.disabled(bool)`, `.mask_toggle()`, `.cleanable(bool)`, `.prefix/.suffix`. Masked text still lives in the rope and undo history until cleared.
- Button: `gpui_component::button::{Button, ButtonVariants as _}`; `Button::new(id).primary()/.ghost().label(..).loading(bool).on_click(|&ClickEvent, &mut Window, &mut App|)`; `.disabled()` needs `gpui_component::Disableable`, `.small()/.large()` need `Sizable`. Button is Styled (`.w_full()`).
- `gpui_component::spinner::Spinner::new()`; `gpui_component::tag::Tag::{info, success, warning, danger, secondary}()` + `.child(..)`.
- Icons: `gpui_component::Icon::new(gpui_kit_assets::IconName::Lock).large().text_color(..)`. Default `gpui_kit_assets::Assets` only embeds ~101 icons (list in `default-icons.txt`; no lock/vault/key). Extras: `gpui_kit_assets::icon_assets!(ExtraIcons, [Lock]);` then a composite `AssetSource` that tries ExtraIcons then `Assets`; register with `application().with_assets(..)`. vault does this in `src/assets.rs`.
- Resizable: `gpui_component::resizable::{h_resizable, resizable_panel, ResizableState}`. `h_resizable("id").with_state(&entity).on_resize(|&Entity<ResizableState>, &mut Window, &mut App|).child(resizable_panel().size(px(220.)).size_range(px(180.)..px(320.)).fixed().child(el))`. `ResizableState::default()`; `state.read(cx).sizes() -> &Vec<Pixels>`. `.fixed()` keeps a panel's width when the window resizes.
- Theme fields used for chrome: `popover`, `border`, `radius`, `radius_lg`, `sidebar`, `sidebar_border`, `accent` (hover bg), `muted_foreground`, `danger/warning/success`, `font_size`.

Verified in P2.6 (main screen):

- Dropdown: `use gpui_component::menu::DropdownMenu as _;` then `button.dropdown_menu(|menu: PopupMenu, &mut Window, &mut Context<PopupMenu>| menu.menu_with_check("Name", checked, Box::new(Action)))`. The menu dispatches via `window.dispatch_action`, so global `cx.on_action` handlers receive it.
- `gpui_component::progress::ProgressCircle::new(id).value(0..=100).color(hsla).size(px(18.)).accessibility_label(..)` is a canvas arc ring. The value transitions with theme motion, so a wrap from 3% to 100% animates.
- Input: `.small()`, `.cleanable(true)`, `.prefix(Icon..)`, `.suffix(div()..)`.
- `Tag::secondary().small().child(..)`. `Icon::new(..).size_4()/.size_3()/.size(px(48.))`.
- Extra icons that exist in gpui-kit-assets 0.8.1: KeyRound, StickyNote, CreditCard, IdCard, Tag, LayoutList, Lock. Defaults include Copy, Eye, EyeOff, ExternalLink, Star, StarFill, SortAscending, Inbox, Search, Plus, Settings, ChevronRight/Down. Variant names live in `target/debug/build/gpui-kit-assets-*/out/icon_name.rs` (grep `grep -rhn "FileBadge\b" target/debug/build/gpui-kit-assets-*/out/`); SVGs in the crate's `assets/icons/<kebab>.svg`. Server + FileBadge are the Server/License template icons (2026-11-15).
- Resizable: `resizable_panel().visible(false)` renders an empty div but keeps the panel's slot in `ResizableState`. To hide a column, vault renders a second `h_resizable` with its own state. `ResizablePanelGroup` has no `.size_full()`.
- `gpui_component::sidebar::Sidebar` was NOT used: it paints from `theme.tokens.sidebar*` (a separate legacy token struct that `Theme::update` field edits do not reach), has no dividers between menus, and its rows are not Tab stops. `SidebarMenuItem` does have `.suffix(..)`, `.active(..)` and collapsible children.

Verified in P2.7 (edit mode, generator, settings), compiled + clippy + headless tests:
- Controlled Popover: `gpui_component::popover::Popover::new(id).anchor(gpui::Anchor::TopRight|BottomLeft..).trigger(button).open(bool).on_open_change(|&bool, w, cx|).content(|&mut PopoverState, w, cx| el)`. `.open()` syncs WITHOUT calling on_open_change; trigger click/Enter/Space, Esc, click-outside DO call it, so write the requested bool back to app state there and give the trigger no `on_click`. Opening moves focus into the content, so Esc inside closes it. Wrapped as `ui::popover` in vault-app.
- Dialog (macOS-sheet-like, slides down): `use gpui_component::WindowExt as _; window.open_dialog(cx, |dialog, w, cx| dialog.title("..").w(px(560.)).child(entity.clone()).on_close(|_, w, cx| ..))`; `window.has_active_dialog(cx)`, `window.close_dialog(cx)`. Root mounts dialog/sheet/notification layers itself. Esc closes and fires `on_close`. Needs `&mut Window`, so global actions set a flag and the root view opens it in `observe_in`.
- Slider: `gpui_component::slider::{Slider, SliderState, SliderEvent}`; `cx.new(|_| SliderState::new().min(8.).max(64.).step(1.).default_value(20.))`; `Slider::new(&e).accessibility_label(..)`; subscribe `SliderEvent::{Change(v), Release(v)}`, `v.end()` = single value.
- `switch::Switch::new(id).checked(b).on_click(|&bool, w, cx|)` (controlled, `.disabled()` needs `Disableable`); `checkbox::Checkbox::new(id).label(..).checked(b).on_click(|&bool, ..|)`.
- Tabs: `tab::{TabBar, Tab}`; `TabBar::new(id).segmented()/.underline().small().selected_index(i).child(Tab::new().label(..)).on_click(|&usize, w, cx|)`.
- Menus with closures: `menu.item(gpui_component::menu::PopupMenuItem::new(label).checked(b).on_click(|&ClickEvent, w, cx|))` inside `.dropdown_menu(..)`. `dropdown_menu` returns a wrapper type, not `Button`: return `impl IntoElement`.
- Multi-line: `input::{TextareaState, Textarea}`; `TextareaState::new(w, cx).auto_grow(3, 10)`; same `text()`, `set_value`, `InputEvent` as InputState. `TextareaState` = `gpui_base::input::InputBaseState<TextareaMode>`, so `focus(window, cx)` is the same generic pub method (tests: `area.update(cx, |a, cx| a.focus(window, cx))`, then `cx.write_to_clipboard` + `simulate_keystrokes("cmd-v")` pastes; a 1 MiB paste into the auto-grow textarea runs fine headless, ~30 s debug). Calling `set_value` on the input from inside its own `InputEvent::Change` subscriber is safe (no re-entrant Change) - used to cut over-limit input (2026-11-07). `Input::new(&s).mask_toggle()` gives the eye toggle on a masked input.
- Input `escape` propagates unless `clean_on_escape`, so an outer `KeyBinding("escape", X, Some("Ctx"))` still fires while typing. `cmd-backspace` in an input is DeleteToBeginningOfLine and does not propagate.
- No sortable list in gpui-component 0.8.1. Use gpui: `div().id(..).on_drag(value, |v, offset, w, cx| cx.new(|_| PreviewView))` on a handle, and `.drag_over::<T>(|style, &T, w, cx| style..)` + `.on_drop(|&T, w, cx|)` on targets. Drag needs a `Render` view for the preview.
- Text tinting: `gpui::StyledText::new(s).with_highlights(vec![(byte_range, HighlightStyle { color: Some(c), ..Default::default() })])`.
- More icons verified to exist (add via ExtraIcons): GripVertical, WandSparkles. Defaults already include Delete, ArrowUp/Down, RefreshCw, ChevronsUpDown.

Verified 2026-10-29 (master password meter):

Verified 2026-10-29 (0.8.1): `Button::icon(..)` on `.with_size(px)` draws the icon at 3/4 of that size (`icon_size` setter is pub(crate) only), so a 28 px square button gets a 21 px, heavier glyph. Verified 2026-10-29 (cursors, 0.8.1):
- Pointer cursor by default ONLY on `Button` link/text variants (`.link()`, `.text()`, e.g. Input's mask toggle and clear "x"). Normal Button calls `cursor_default()` then re-applies the caller's style last, so `.cursor_pointer()` on a Button wins; disabled/loading keep the caller's cursor too, so set it conditionally. Switch, Checkbox, Tab, Slider and PopupMenu rows set no cursor (disabled Switch shows not-allowed); all but menu rows are Styled and take `.cursor_pointer()`.
- PopupMenu rows have no style hook. Pointer workaround: `PopupMenuItem::element(|_, _| h_flex().relative().flex_1().self_stretch()...child(div().absolute().top_0().bottom_0().left(px(-8.)).right(px(-8.)).cursor_pointer()))` (8 px = private INNER_PADDING); render the check mark yourself. vault: `ui::menu_item`.
- Dialog's built-in close button (absolute top-right, gpui-base `DialogClose`) keeps the arrow: use `.close_button(false)` and put your own button in `.title(element)` (title accepts any element; give it `w_full()`).
- gpui-component Switch's outer wrapper has no element id; the inner gpui-base switch carries the id.
- Clicking a Switch in tests: its built-in debug selectors (`switch-bar`, `switch-label`) are not unique per switch; wrap it in `div().debug_selector(|| "my-switch".into())` and `vcx.simulate_click(bounds.center(), Modifiers::none())` toggles it (verified 2026-11-08, Dock row test).
- vault-app rule: every click target goes through `ui::Clickable` (`.clickable()` / `.clickable_when(enabled)`; false sets the arrow explicitly). `ui::icon_button` already includes `.clickable()`.

Verified 2026-10-30 (no-categories change): `IconName` (generated in gpui-kit-assets build.rs) derives Clone, Copy, Debug, Eq, PartialEq, Hash, so `format!("{icon:?}")` gives "KeyRound" and works in debug selectors. `Tag` implements `Styled` (`Tag::secondary().small().flex_none()` compiles). Removable chip (Tag small + xsmall icon button) is 26 px tall vs 24 px for the small Input at rem 13: a wrapping chip row grows 2 px on the first chip. Fix that kept layout stable: `h_flex().id(..).flex_none().h(theme::scaled(28.))` + `.items_center().overflow_x_scroll()` (no `flex_wrap`), children `flex_none`.

Verified 2026-10-30 (backup delete): gpui-component 0.8.1 `Button::accessibility_label` is a plain setter (`Option` overwrite), so `ui::icon_button(id, icon, "Delete backup").accessibility_label(format!(..))` gives a short tooltip and a longer VoiceOver label. Verified 2026-10-31 (icon picker popover):
- gpui-component `Popover::track_focus(&FocusHandle)`: on open, focus moves to YOUR handle (put it on the content root with `track_focus` + `key_context`), else to the popover's own content node, which is an ANCESTOR of your content (child `on_key_down`/`on_action` never fire). gpui-base binds `escape` → Cancel and `enter`/`space` → `gpui::NoAction` in context `PopoverContent`; your own bindings in a deeper context (e.g. "IconPicker": up/down/left/right/enter → actions) win. Esc still closes via on_open_change(false) and does not reach an outer `escape` binding. Mutation-checked.
- `IconName` has no FromStr / name lookup; it has `IconName::ALL` and `.path()` ("icons/x.svg"). Persist names via your own const table and test `format!("{icon:?}") == name`. There is no `Home` (use `House`). Most Lucide names (Landmark, Wallet, Mail, Cloud, Server, Car...) are NOT in default-icons.txt; check `default-icons.txt` by full path ("icons/x.svg") and add the rest to `ExtraIcons`; vault has a test that every curated symbol loads through `AppAssets`.
- Button as a popover trigger around an arbitrary element: `Button::new(id).ghost().p_0().w(px).h(px).child(el)`.

Verified 2026-11-07 (shared `ui::menu_popover` / `ui::menu_row`, replaces PopupMenu for app menus):
- gpui-component `Popover` content = `v_flex().popover_style(cx).p_3()...refine_style(&self.style)`: the Popover's own `Styled` style is applied AFTER `p_3`, so `Popover::new(..).p(px(4.))` overrides the padding and keeps bg/border/shadow/rounding. `trigger_style` is separate. `.appearance(false)` would drop all chrome.
- Per-popover focus handles that must exist at builder time (for `Popover::track_focus`): `window.use_keyed_state(SharedString id, cx, |_, cx| State { handles })` called from the view's render (works in `render_list`); the call needs `&mut App`, so build the popover before holding `state.read(cx)`/`cx.theme()` borrows.
- gpui-base `transition_to(open)` focuses the tracked handle THEN calls `on_open_change`, so a wrapper can re-focus something else (vault: click-open focuses the panel, keyboard/app-state open leaves the first row focused). Controlled `.open(true)` (⌘N) focuses the tracked handle without calling the callback.
- Row handles: `cx.focus_handle().tab_stop(true)` (default `tab_stop` is false; a tracked handle's own flags decide the tab stop, the div's `.tab_index` does not change them). ↑/↓ via own actions in a nested key context; `escape` still hits PopoverContent's Cancel → on_open_change(false). Enter/Space on a focused row fire `on_click` on key UP (tests send KeyUpEvent).
- `window.focus_next()` ignores tab groups for confinement (groups only order), so it would leave a menu; use explicit handles.
- In a bare test window with nothing focused, `simulate_keystrokes("tab")` does not focus a Button trigger; open via app state after any key press instead.
- Button trigger keyboard open works: since 2026-11-08 Sort follows the detail column: click the first sidebar row (`nav All Items icon=LayoutList`) and Shift-Tab ×3 (New, generator, Sort), Space (down+KeyUp) toggles the Popover open via `on_open_change(true)` (verified step B, 2026-11-07). Menu rows' check mark carries debug selector `<row-id>-checked` for assertions. `VisualTestContext::debug_bounds` needs `&mut`.
- Sort / Add field / Templates menus all use `menu_popover` with open state in `AppState` (`sort_menu_open`, `add_field_menu_open`, `template_picker`); a row's on_click must close its own menu (the popover does not). Settings `choice` dropdowns still use `ui::menu_item` + `dropdown_menu` (PopupMenu).
- Content-sized menu panel (verified 2026-11-07): Popover content is anchored/absolute, so it fits its content. Inner `v_flex().max_w(px(320.))` with NO width; rows without `w_full` stretch to the widest row; label `flex_1().min_w_0().truncate()` keeps its natural width (max-content) until max_w, then truncates. `ui::focus_ring` adds a 1 px border, so measured insets are padding + 1: subtract `FOCUS_RING_WIDTH` from padding for exact x. Menu-wide flags (any icon / any checkable row) are computed in `menu_popover` and passed to `MenuRow::render`; `MenuRow::checked(b)` marks checkable. Selectors: `<id>-panel`, `<row>-label`. Test-measured inner widths: Templates 107, Sort 173, Add field 113 px.
- `VisualTestContext::debug_bounds(&'static str)`: for formatted selectors in tests, `Box::leak(s.into_boxed_str())`.
- vault main list (2026-11-08, option A): `list_focus` is `cx.focus_handle().tab_stop(true)`, one Tab stop; rows never. Sort, generator and footer New Buttons use `.tab_index(1)` so the ring is sidebar rows → toggle → search → list → detail → Sort → generator → New. `Button::tab_index(n)` DOES reorder a gpui-component Button, even with `Button::track_focus(&h)` and a plain `cx.focus_handle()`: the Button's own tab_index/tab_stop (default 0/true) win over the handle's flags, so set `.tab_index` on the Button, not the handle (verified 2026-11-08; without it the tracked handle sat at index 0). Vault keeps `MainScreen::sort_focus` this way so tests can assert the Sort trigger is focused.

Verified 2026-11-15 (edit-mode field rows, 0.8.1):
- Borderless "ghost" Input that still rings on focus: `Input::new(&s).small().bg(gpui::transparent_black()).border_color(gpui::transparent_black())`. Input is `Styled` (`refine_style` runs after the appearance bg/border), while the focused border (`styles.focused(border_1 ring)`) and `focus_ring_style` apply after it, so the ring still shows and the 1 px transparent border keeps layout fixed. Do NOT use `.appearance(false)`/`.bordered(false)`: those also drop the focus ring. `Textarea` is Styled too and forwards its refinement to the inner Input (`into_input().refine_style`), so the same two calls work.
- Input text colour/weight/font come from inherited text style: `.text_color(..)`, `.font_weight(..)`, `.font_family(theme.mono_font_family.clone())` on `Input` work (the editor element paints `window.text_style().color`); the placeholder always uses `theme.muted_foreground`. For focus-dependent colour compute `focus_handle(cx).is_focused(window)` in render (gpui-component does the same for its ring).
- `InputState` and `TextareaState` are both `InputBaseState<M>`, which implements `Focusable`: `gpui::Focusable::focus_handle(&entity, cx)` works for both.
- `Button::track_focus(&handle)` takes a caller-owned FocusHandle (skips the keyed `use_keyed_state` handle). Keep handles in the row struct: "row has focus" = any of its handles focused, and focus stays on the button when the row is reordered (Space on a focused ↑ moves the row and ↑ stays focused).
- Assert the focus ring headlessly: `window.painted_quads()` with `q.border_color == cx.theme().ring && q.border_widths.left.0 > 0.`, bounds divided by `window.scale_factor()`; compare to the input holder's debug_bounds (test: editor_row_tests.rs).
- (2026-11-16) gpui-component `Button` calls `window.prevent_default()` on left mouse down ("avoid focus on mouse down"): a click NEVER focuses a Button; only Tab does. So "button has focus" already means keyboard focus, unless focus got there by Tab and the user clicked elsewhere without moving it (vault also gates on `ui::focus_ring_allowed()`).
- A tracked (caller-owned) FocusHandle ignores the element's `.tab_index()/.tab_stop()` (div.rs applies them only to internally created handles): create it as `cx.focus_handle().tab_stop(true)` to be a Tab stop. To keep hover-only buttons Tab-reachable without rendering them, draw a cheap placeholder `div().id(..).size_6().track_focus(&same_handle).tab_index(0)`; Tab focuses the handle and the next render swaps in the real Button on the same handle (`.invisible()` would drop the Tab stop).
- An `Input` sets its own text size (`input_text_size`) before `refine_style`, so a wrapper div's `.text_xl()` does not reach the text; style the Input itself. Headless text-size check: `state.read(cx).range_to_bounds(&(0..len))` width vs `window.text_system().shape_line(text, size, &[style.to_run(len)], None).width` with the expected `TextStyle` (refine via `gpui::Refineable::refine(&mut style, &refinement.text)`); a tiny `Styled` holder struct reads a style helper's refinement back.

Verified 2026-11-16 (icon picker search field, 0.8.1 / gpui-pre 0.3.10):
- Single-line Input SWALLOWS `up`/`down` (MoveUp/MoveDown no-op, no propagate) and `left`/`right`; `enter` (Enter) and `escape` (Escape, unless clean_on_escape) DO propagate. gpui dispatch tries every matching binding in precedence order while the action propagates, so an ancestor context's `enter`→MyChoose / `escape`→MyClose still fire after the Input's own action.
- To steer arrows from a focused Input to an ancestor: `.capture_action(|_: &gpui_component::input::MoveUp, w, cx| { ..; cx.stop_propagation() })` on the ancestor (MoveUp/Down/Left/Right are re-exported from `gpui_component::input`).
