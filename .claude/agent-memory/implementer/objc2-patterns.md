Versions that compiled together (2026-10-29): objc2 =0.6.5, objc2-foundation/app-kit/core-graphics =0.3.2, block2 =0.6.2 (dropped from vault-macos after the switch to selector observers). Use default-features=false + explicit features ("std", "block2", "NSString", "NSNotification", "NSDistributedNotificationCenter", "NSOperation", "NSObject"; app-kit "NSWorkspace"; core-graphics "CGEventSource","CGEventTypes").

- Notification observer: `center.addObserverForName_object_queue_usingBlock(Some(name), None, None, &RcBlock::new(move |_: NonNull<NSNotification>| ..))` is `unsafe`; returns `Retained<ProtocolObject<dyn NSObjectProtocol>>`.
- `removeObserver` takes `&AnyObject`: upcast via `let o: &AnyObject = (*token).as_ref();`.
- NSDistributedNotificationCenter -> NSNotificationCenter: `Retained::into_super(center)`.
- `NSWorkspace::sharedWorkspace().notificationCenter()` needs no MainThreadMarker.
- Extern statics such as `NSWorkspaceWillSleepNotification` need `unsafe` to read.
- CoreGraphics: use the safe `CGEventSource::seconds_since_last_event_type(CGEventSourceStateID::HIDSystemState, ..)`. The free fn is deprecated. `kCGAnyInputEventType` is NOT exported, so use `CGEventType(u32::MAX)`.
- Subscribing and dropping both observers works in headless `cargo test`, with no run loop needed.
- `cargo info <crate>` shows the lockfile version when the crate is already locked, so it is not always the latest.
- Selector observer: `define_class!(#[unsafe(super(NSObject))] #[ivars = Ivars] struct Observer; impl Observer { #[unsafe(method(handle:))] fn handle(&self, _n: &NSNotification) {..} })`. `#[ivars = ..]` must be a path, so use a named struct. Init with `Self::alloc().set_ivars(..)` then `unsafe { msg_send![super(this), init] }`; needs the `AnyThread` and `DefinedClass` imports.
- `Mutex<Box<dyn Fn() + Send>>` in the ivars makes the class Send + Sync automatically, so no `unsafe impl Send` is needed on guards.
- Distributed center: `addObserver_selector_name_object_suspensionBehavior(.., NSNotificationSuspensionBehavior::DeliverImmediately)`.
- Suspension findings (2026-10-29, macOS 27): with `center.setSuspended(true)` and a post from a CHILD process, a selector observer using Coalesce or Hold is held, and DeliverImmediately is delivered. The block API (addObserverForName..usingBlock) was delivered while suspended. Posting from your own process skips suspension, so post from a child for tests.
- Integration tests that need the main run loop use `harness = false` plus a `fn main`, and pump `NSRunLoop::currentRunLoop().runUntilDate(..)`.
- NSArray `.iter()` needs the NSEnumerator feature; use `containsObject(&x)` instead. `NSArray::from_slice(&[key])` and `from_retained_slice` work.
- NSURL resource values: safe `url.resourceValuesForKeys_error(&keys)?.objectForKey(key)` gives `Retained<AnyObject>`; then `.downcast::<NSNumber>()` / `NSString`. Use a fresh NSURL per poll to avoid cached values. Foundation key/status constants are extern statics (unsafe read). Compare NSStrings with `*a == *b`.
- NSPasteboard: `generalPasteboard()` needs no MainThreadMarker. `declareTypes_owner` is unsafe (nil owner is fine). `setString_forType`, `changeCount`, `clearContents`, `types`, `stringForType` are safe. Features: app-kit "NSPasteboard", "NSAccessibility" (reduce motion lives on NSWorkspace).
- atime-only touch on possibly-iCloud files: use `libc::utimensat(AT_FDCWD, cpath, [UTIME_NOW, UTIME_OMIT], 0)`. std `File::set_times` needs an open fd, and opening an evicted placeholder materializes it (it can hang Drop on quit). Reviewer flagged this in P4.1.
- Bulk regex edits with `\Z` swallow trailing `mod imp` blocks. Anchor replacements to the end of the function.
- Security/LocalAuthentication (P4.2, 2026-10-29): objc2-security, objc2-core-foundation, objc2-local-authentication all `=0.3.2`. Every Sec* call is `unsafe` (out-pointers). Build query dicts as `CFDictionary::<CFString, CFType>::from_slices(&keys, &vals)` and pass `.as_opaque()`. `.into()` to the opaque dict does NOT compile. `CFBoolean::new(true).as_ref()` gives `&CFType`. `CFData::from_buffer` is deprecated, use `from_bytes`. Extern `kSec*` statics need unsafe reads. Take ownership of a +1 out-param with `CFRetained::from_raw(NonNull)`. Use `CFRetained<CFType>::downcast::<SecKey/CFData>()`. LAContext as a CFType: `&*Retained::as_ptr(&ctx).cast::<CFType>()`. CFError: `.code()`, `.domain()` (Display gives the string; LA domain is "com.apple.LocalAuthentication").
- security-framework 3.7 was rejected: GenerateKeyOptions has no application tag and there is no LAContext/kSecUseAuthenticationContext.
- Data protection keychain (`kSecUseDataProtectionKeychain`) from an unsigned `cargo test` binary returns errSecMissingEntitlement -34018, even for delete or lookup. Ad-hoc `codesign --entitlements` with keychain-access-groups gets the binary SIGKILLed by AMFI (exit 137). A real Developer ID plus a provisioning profile is needed, so tests must tolerate -34018.
- Biometry-change detection: BiometryCurrentSet SE keys fail decryption with errSecAuthFailed (-25293), not -67712. biometric.rs stores `LAContext.evaluatedPolicyDomainState` (deprecated in macOS 15, needs `#[allow(deprecated)]`; LADomainState is 15+ only) in the payload and compares it before prompting. Read a nested LAError via `err.user_info()` plus `cast_unchecked::<CFString, CFType>()`, then `.get(kCFErrorUnderlyingErrorKey)` (an `Option` static). Tests build CFErrors with `unsafe CFError::new(None, Some(&domain), code, Some(dict.as_opaque()))`.
- ServiceManagement (P5.4a, 2026-10-29): objc2-service-management =0.3.2 with default-features=false, features ["std","SMAppService","objc2","objc2-foundation"]. Every SMAppService method is `unsafe` (mainAppService, status, register/unregisterAndReturnError -> Result<(), Retained<NSError>>, openSystemSettingsLoginItems). SMAppServiceStatus is a newtype with consts, so a match needs a `_` arm. `NSBundle::mainBundle().bundleURL().pathExtension()` is safe (objc2-foundation feature "NSBundle"). status() from a bare test binary takes about 2s on the first call, but it does not fail.
- Screen capture (P5.7, 2026-10-29): `CGDisplayCreateImage` (deprecated, needs `#[allow(deprecated)]` on BOTH the `use` and the call) still links and runs on macOS 27. core-graphics features: CGDirectDisplay, CGDisplayConfiguration, CGError, CGImage, CGColorSpace, CGContext, CGBitmapContext, CGWindow (Preflight/RequestScreenCaptureAccess live in CGWindow). CGRect/CGPoint/CGSize need objc2-core-foundation feature "CFCGTypes". `CGBitmapContextCreate` is in the hand-written `bitmap_context.rs`, not generated, is `unsafe`, and takes `bitmap_info: u32` (pass `CGImageAlphaInfo::None.0`). Renamed safe methods: `CGImage::width(Some(&img))`, `CGColorSpace::new_device_gray()`, `CGContext::draw_image(Some(&ctx), rect, Some(&img))`. Drawing into a bitmap context puts the image top row at buffer row 0 (unit-tested). The dev terminal has NO Screen Recording grant, so live capture is unverified, and running the ignored test triggers CGRequestScreenCaptureAccess.
- rqrr 0.11 with default-features=false avoids the image crate; use `PreparedImage::prepare_from_greyscale(w, h, |x, y| u8)`. Grid.bounds[0] is top-left. qrcode 0.14 with default-features=false still has `to_colors()` and `width()`.
- Image files (P5.7b, 2026-10-29): app-kit features "NSImageRep", "NSBitmapImageRep", "objc2-core-graphics" (the last one gates `initWithCGImage` / `.CGImage()`); foundation "NSData" for `NSData::with_bytes` / `to_vec`. `NSBitmapImageRep::initWithData(NSBitmapImageRep::alloc(), &data)` is safe and decodes LAZILY: a valid 100 MP PNG costs ~5 MB at init, so check `pixelsWide/High` (on `&NSImageRep` via deref) before drawing. `representationUsingType_properties` is unsafe; pass `NSDictionary::<NSString, AnyObject>::new()`. ImageIO REJECTS hand-built PNGs whose IDAT is truncated (even a valid partial zlib stream), so test size caps with a real encoded image (10000x5001 white PNG takes ~1s).
- Reading user-picked files (review fix, 2026-10-29): open with `OpenOptions::custom_flags(libc::O_NONBLOCK)` and check `file.metadata()?.is_file()` on the handle. A plain `File::open` on a FIFO with no writer blocks forever, and /dev/zero reports len 0, which passes size checks. Test FIFOs with `libc::mkfifo` and run the scan on a thread with `recv_timeout`.
- Hardening (2026-10-29): `prepareForNewContentsWithOptions(NSPasteboardContentsOptions::CurrentHostOnly)` is safe and needs app-kit feature "bitflags". Do NOT follow it with `declareTypes:owner:` (that clears again and drops the option); `setString:forType:` adds the types itself. Write the ConcealedType marker BEFORE the text (`types()` order follows write order, so it is testable) and `clearContents` on any failed write. NSWindow is MainThreadOnly, so `setSharingType` on `&NSWindow` is safe. Test NSWindow creation in a harness=false test with `NSApplication::sharedApplication(mtm)` plus `initWithContentRect_styleMask_backing_defer(NSWindow::alloc(mtm), ..)` with defer=true and `setReleasedWhenClosed(false)`; that works headless, and NSApp.windows() lists the windows. NSRect in tests needs foundation feature "NSGeometry". NSWorkspace's notificationCenter is in-process, so a test can `postNotificationName_object` the workspace notification itself and gets synchronous delivery.
- Accent colour (2026-10-29): app-kit features "NSColor", "NSColorSpace", "objc2-core-foundation" (the last gates `getRed_green_blue_alpha`, which is unsafe with `*mut CGFloat` outs; CGFloat from objc2_core_foundation). `NSColor::controlAccentColor()`, `colorUsingColorSpace(&NSColorSpace::sRGBColorSpace())` and the `NSSystemColorsDidChangeNotification` static (unsafe read) are otherwise safe. NSColor is Send, not MainThreadOnly, so the main-thread rule is enforced by hand with `MainThreadMarker::new()?`. `NSNotificationCenter::defaultCenter()` posts synchronously in-process, like the workspace center.
