# 05 — `vault-app`: UI

Framework: `gpui` + `gpui-component`, versions pinned with `=`. Treat gpui as pre-1.0: wrap any API we touch in more than two places behind our own thin helper so an upstream rename is a one-file fix.

Reference look: 1Password 8 for macOS. Three columns, 13 pt system font, generous whitespace, subtle borders rather than heavy chrome, native-feeling vibrancy on the sidebar in light mode.

The app name is **Vault** in user-facing text, including menus, welcome and About screens. Use lowercase “vault” for an individual vault or vault file.

## 1. Window and layout

Single main window, 1100×720 default, min 820×520, state persisted (size, position, column widths) in `~/Library/Application Support/<bundle id>/window.json`. Title bar: hidden-title transparent style with traffic lights inset; the sidebar extends under it.

```
┌─────────────┬──────────────────────┬────────────────────────────────┐
│ Sidebar     │ Item list            │ Detail                         │
│ 220 px      │ 300 px               │ fill                           │

│ All Items   │ │ 🔍 Search   ⌘F   │ │  ─────────────────             │
```

Columns are resizable via gpui-component's resizable panel; sidebar collapsible with `⌃⌘S` (View ▸ Hide Sidebar / Show Sidebar; 2026-10-31, Apple Passwords style). Collapsing removes the sidebar from the layout: the list keeps its width, its search row starts after the traffic lights (82 px inset), the sidebar toggle button stays at the left of the search row in both states, and the list shows the active filter ("All Items", "Favorites", "#tag") with its muted count above the rows only while collapsed. The state is remembered per app in settings.json, defaults to expanded, slides over 180 ms and is instant under Reduce Motion. While collapsed the window minimum width drops from 820 to 600 (via `vault-macos` `window::set_min_content_size`). The sidebar has no bottom bar and the window has no Settings or Lock button (owner decision 2026-10-31, as in 1Password and Apple Passwords): Settings is reached only through `⌘,` and the app menu; Lock only through `⌘L` and File ▸ Lock.

## 2. Screens / states

### 2.1 Launch → choose vault
First run, or no vault remembered: card with "Create new vault" / "Open existing vault…" / recent vaults list. Create flow: name, location (folder picker; shows a hint badge when the chosen folder is inside iCloud Drive or Dropbox), master password + confirm with live strength meter (same scale as the generator) and a minimum of 50 bits per `generator::strength_bits` (Create stays disabled below it, inline message "Choose a stronger master password (at least 50 bits). Try a 4-word passphrase."), a "Suggest passphrase" link that fills both fields with a generated 4-word passphrase revealed once plus the note "Write it down. There is no recovery without it.", "Calibrating encryption for this Mac…" spinner (KDF calibrate), done. The same meter and minimum apply to Change master password. The minimum is enforced in the UI and the CLI (`--allow-weak` bypasses it there), not in `vault-core`.

### 2.2 Unlock
Centered card: the app icon at 128×128 (PNG raster of assets/icon), vault name, password field (autofocus), "Unlock" button, Touch ID button if enrolled (triggers automatically on appear if enrolled and policy allows), Passkey button if a passkey slot exists (post-phase-5, macOS 15). While a password or Touch ID unlock is in progress, hide the controls without changing the card size and show "Unlocking…". The icon's six-arm wheel rotates with ease-in-out motion in an infinite loop while the rest of the icon stays still, implemented as a rotated SVG layer over the static PNG (no frame animation asset). Reduce Motion keeps the icon still. "Unlocking…" stays up for at least 500 ms from the start of a password or Touch ID unlock: a faster result (success or failure) is held until then, a slower one shows as soon as it arrives, and a lock or vault switch during the hold discards it; Reduce Motion stills the wheel but keeps the hold. Successful unlock focuses Search. Wrong password: field shakes (only on a failed attempt; the card never shakes when the screen appears after a lock), inline error, no lockout counter in v1. `⌘O` switches vault. A vault with no slot this version can use shows "This vault was created by a newer version of Vault" instead of the password field.

### 2.3 Main (locked → unlocked transition is a 150 ms crossfade)

**Sidebar** (categories removed 2026-10-30): All Items, Favorites, then the Tags section (collapsible, sorted alphabetically) — no Logins/Notes/Cards/Identities rows. Counts shown right-aligned in a muted color. Template tags carry an icon instead of the generic tag glyph: `#login` key, `#note` sticky note, `#card` credit card, `#identity` id card; all other tags use the tag glyph. Settings opens a sheet (not a separate window) from `⌘,` or the app menu; there is no Settings button in the window (2026-10-31).

**New item** (`⌘N`): a Templates menu — Login, Note, Card, Identity — each a preset of fields plus one tag (`#login`, `#note`, `#card`, `#identity`) added automatically; the item has no category. More templates may be added later as field presets only. The detail header shows the title only (no kind label).

**Item list**: search field pinned at top and focused after unlocking; rows are 56 px: 32 px item icon (2026-10-31: a symbol or tinted letter chosen in edit mode, else a custom image stored as a hidden attachment, else the bundled Simple Icons brand logo for the first URL field's registrable domain label, else the letter avatar from the title with a deterministic colour from the id hash; near-white brands, and near-black brands in dark appearance, sit on a neutral tile with the glyph in the brand colour only at ≥ 3:1 contrast), title (semibold), subtitle (username / card last-4 / first line of note; a field named "username" is only used when its kind is not sensitive), favorite star right-aligned, then a red "!" badge when the item has a weak (< 40 bits) or reused password (tooltip "Weak password" / "Reused password"). The audit runs once per vault change and is cached on the listing. Grouped by first letter when sorted A–Z; sort menu: A–Z, recently modified, recently created. Empty state illustration + "Create your first item" when the vault is empty; "No results" with "Create '<query>'" when search is empty. Virtualized list. Double-clicking a row opens a movable read-only window pinned to that item's live details, with reveal and copy controls (owner-approved 2026-10-30). One window per item: a second double-click focuses the existing one. Windows are tracked in `AppState`, closed on lock, vault switch and item deletion, titled with the item's name, following renames live, "Untitled" when blank, trimmed to 120 characters (owner decision 2026-10-31, replacing the earlier fixed "Item details" title; the name is therefore visible in Mission Control and the Window menu while the window is open), and re-render once a second only while the item has a TOTP field.

Value areas in both the main detail view and item windows copy on click, or Enter/Space when focused, with the same pointer cursor, hover highlight and "Click to copy" tooltip. Masked passwords copy without being revealed; TOTP fields copy the current code. Item windows always copy from their pinned item, independently of the main selection.

Both hosts use the same read-mode detail renderer: header (title only), tags, warning cards, field fonts and colours, row spacing, TOTP countdown, password history, attachment row styling and modified footer. Copy feedback is the same transient pill in the window where copying occurred; it disappears after two seconds. Each item window keeps its own reveal and history-disclosure state. Editing controls remain in the main window.

**Detail**: read mode by default. Each field uses a horizontal row inspired by macOS Passwords (shared `detail::field_row`, also used by the item window and the backup viewer): the label on the left in the foreground colour, its value on the right in the muted foreground colour (masked dots, revealed secrets and notes included; links, the urgent TOTP colour and the copy/reveal icons keep their own), with 7 px top and bottom padding (owner decision 2026-10-31, for readability); the rule under the tags and the rows form one group, so the first row sits 7 px under the rule like every other row. Template fields are created with natural labels from a per-field table ("Username", "Password", "Website", "Notes", "Number", "Expiry", "CVV", "Name", "First name"); every app-side lookup by field name is case-insensitive so imported or CLI-created lowercase names behave the same; read-only labels render with the first character capitalised for display and stored names are never rewritten (2026-10-31). In edit mode, "Add field" pre-fills the kind's capitalised label ("Text", "URL", "One-time code", numbered on a case-insensitive collision) and a new field's name has its first character capitalised once when first typed; existing names, template fields and values are never changed. The detail fade-in is keyed on the selection only, so Edit and Cancel do not replay it. Labels and values align in consistent columns; long labels wrap, notes retain multiple lines, and the layout adapts to narrower detail panes. The same layout applies to item windows. Fields rendered per `FieldKind`:
- `text`, `email`, `url`: value + copy; `url` also gets "open in browser"
- `password`: dots, reveal toggle (`⌘⇧R`), copy (`⌘⇧C`), strength meter under it in edit mode, history disclosure (last 10 values with timestamps, each copyable)
- `totp`: 6-digit code grouped as `482 193`, circular countdown ring, copy; auto-refresh every second; code turns amber under 5 s
- `notes`: multiline, markdown **not** rendered (plain text)
- `card`: number shown as `•••• •••• •••• 4242`, reveal toggle
- `date`, `month_year`: plain (`number` removed; an old `number` field renders as an unknown kind)
- unknown kind (from a newer version): masked like `password`, with reveal and copy; the field's original kind string is shown as its label

Above the fields, one banner per issue when the item has a weak or reused password: red "!" icon, bold title "Weak Password" / "Reused Password", body "This password is easy to guess and should be changed." / "This password is used by N other items. Reuse lets one leak unlock several accounts." Not dismissable; it disappears when a saved edit fixes the password. Tags render as `#tag` chips under the title. Exactly one rule separates the last field from the "modified … · device" footer.

**Item icon picker** (2026-10-31): in edit mode the 44 px header tile opens a popover with an "Automatic" row (shows what automatic resolves to and clears the stored icon), a grid of 40 symbols, 8 colour swatches, and "Drop or choose image…" (click opens a panel limited to PNG and JPEG files; the row and the header tile both accept a dropped file; PNG or JPEG, input ≤ 512 KB and ≤ 8192 px per side, downscaled to a 128 px PNG at drop time and stored through the attachment path as `icon { kind: "image", value: <attachment id> }`; the original is not kept; when rendering, a stored icon blob over 256 KB or 256 px per side, or one that fails to decode, is refused and the automatic icon shows instead; decoded tiles are cached per attachment id, at most 128, cleared on lock). Shape and colour are independent (2026-10-31): "Automatic" is the shape whenever no symbol is chosen and stays selected when a colour is picked; the colour row always shows the effective colour with the item's palette colour pre-selected (picking it again clears the override; no marker: the Automatic row's mini tile previews the effective shape and colour live); when Automatic resolves to a brand logo the colour row is disabled with the hint "Logos use the brand colour". Storage: Automatic + default → no icon; Automatic + colour → kind `letter` with the colour, which means "automatic shape with a colour override" (a matching logo still wins, otherwise a tinted letter); symbol + default → `symbol` without colour; symbol + colour → `symbol` with colour. The icon blob never appears in any attachment list, count, window or the backup viewer; an older build shows it as an ordinary attachment. Choices save or cancel with the edit; arrows move, Enter picks, Esc closes the picker and returns focus to the title field. The same tile is used in the list row, the detail header, the item window and backup rows.

**Attachments** section below the fields (v1.1): one row per file with a document icon, name, size, and state (present / "Not downloaded yet" / "Missing"). Actions: Preview (in-app only for images and UTF-8 text under 1 MB; other kinds have no preview), "Save decrypted copy…" (NSSavePanel; confirm sheet "This writes an unencrypted copy to disk."), Remove (in edit mode or via the row's menu). Add via "Add file…" (open panel) or by dropping files onto the detail column; files over 100 MB are refused with a toast. Adding and saving run as background tasks with the usual lock guard. Attachments are not backed up (owner decision); the backup viewer shows them as Missing.

Copy shows a transient "Copied — clears in 30 s" pill at the bottom of the detail column.

**Edit mode** (`⌘E` or Edit button): title becomes editable, each field gets name/value inputs, "Add field" menu with kinds, field drag-to-reorder, "Generate" button inside password fields opens the generator popover. A tags row under the title, always rendered in edit mode at a fixed height so adding the first tag does not shift the layout: existing tags as chips with ×, an "Add tag" input where Enter or comma commits (trimmed, leading `#` stripped, case-insensitive dedupe, insertion order; Backspace in the empty input removes the last chip); a pending draft is committed on Save and discarded on Cancel. TOTP fields show a validity line while editing ("Valid one-time code" / "Not a valid otpauth URI or base32 secret"); on save a touched TOTP value is trimmed and a bare base32 secret is wrapped into an `otpauth://totp/<title>?secret=…` URI, untouched fields are left byte-identical. TOTP fields have "Scan QR from image…" (file picker; the screen-capture scan was removed on 2026-10-29 because it needs Screen Recording permission). "Add field" offers Text, Password, One-time code, URL, Notes, Email, Date, Month/year (capitalised); `number` is not offered but still renders on existing items. A scan result lands only in the field it was started from and is discarded if the vault locked meanwhile. Fields of unknown kind use the masked input and are not offered in "Add field". Save `⌘S` / Cancel `Esc`. Unsaved-changes guard when navigating away: inline "Discard changes?" confirm, not a modal.


### 2.4 Password generator (popover, also `⌘G` globally)
Tabs: Password / Passphrase. Live preview (monospace, symbols tinted, digits tinted), length slider 8–64, class toggles, exclude-ambiguous, regenerate button, copy, "Use" (when opened from a field).

### 2.5 Settings sheet
Tabs:
- **General**: auto-lock after (1/5/15/60 min/never), "Lock on sleep, screen lock or user switch" (on; one setting covers all three), clear clipboard after (15/30/60/90 s), launch at login (off, phase 5), appearance, text size
- **Security**: Touch ID toggle, Passkey toggle (post-phase-5), change master password (same meter and 50-bit minimum as create), re-calibrate KDF ("Encryption strength: ~0.6 s on this Mac"), rotate vault key (advanced, collapsed; drops Touch ID enrolment)
- **Sync & Backup**: vault path with "Move…" and "Reveal in Finder", status line (last synced, cloud provider detected), backups list with Open / Restore… / Delete (trash icon; inline "Delete this backup?" confirm; removes the snapshot file or conflict package from `backups/`; no undo), "Back up now", retention multiplier
- **Import / Export**: CSV, 1PUX, KDBX import; the initial "Export CSV…" button uses neutral styling, with the warning strip and final "Export…" confirmation styled red
- **About**: version, licenses

KeePass import is available from Settings and File ▸ Import KeePass (KDBX)… . After selecting a file, show an inline password prompt with optional key-file chooser, explicit import scope, Cancel and Import. Clear the password after submission, cancellation, hiding the form, or lock. Read and decrypt on the background executor; discard completion after cancellation, lock or vault switch. Incorrect credentials leave the prompt open for retry. Successful import creates new items and uses the ordinary autosave flow; the source database is never written.

## 3. State model

One `AppState` entity (gpui `Entity<AppState>`) owning:

```rust
pub struct AppState {
    pub vault: Option<SyncedVault>,          // None = no vault chosen
    pub locked: bool,
    pub selection: Option<Uuid>,
    pub filter: Filter,                       // All | Favorites | Tag(String)
    pub query: String,
    pub sort: Sort,
    pub mode: Mode,                           // View | Edit(EditBuffer) | New(Template, EditBuffer)
    pub toast: Option<Toast>,
    pub sync_status: SyncStatus,
    pub settings: Settings,
    pub last_activity: Instant,
}
```

Views subscribe to `AppState` and re-render on `notify()`. Derived data (`filtered_items: Vec<Uuid>`) is recomputed on `query`/`filter`/`sort`/vault change and cached in state, not recomputed per frame.

`EditBuffer` is a plain clone of the `Item` being edited; Save calls `vault.edit(|v| v.update(id, now, |it| *it = buffer))`. Core recomputes field timestamps by diff (see 02 §`update`).

Sync events arrive on a `crossbeam_channel` receiver polled from a gpui background task; each event mutates `AppState` on the main thread and `notify()`s. `Merged` while editing: keep the edit buffer, show a toast "Vault updated from another device"; if the merged item is the one being edited and a field the user has touched changed remotely, mark that field with a small badge "changed remotely — your edit will win on save".

Auto-lock: a 1 s timer checks `vault_macos::seconds_since_user_input()` and `last_activity`; on threshold → `lock()`. Lock = close the Settings sheet, any toast, and every backup-viewer window; save if dirty; `vault.lock()`; clear selection and edit buffer; clear clipboard if ours; switch to Unlock screen. Every trigger (⌘L, idle, screen lock, sleep, user switch, key mismatch, window close, quit) goes through the same `lock()`. A background task (QR scan, Touch ID, save) that completes after a lock discards its result silently. Every new window is excluded from screen capture (best effort, `04` §3b).

## 5. Theme

Use gpui-component's theme system. Define our tokens on top:

```
accent         follows the macOS accent colour (NSColor.controlAccentColor, re-read on NSSystemColorsDidChange); fallback light: #3B6CF0   dark: #5B8CFF; text on accent is white, flipping to dark only when contrast would fall below 2:1 (yellow), matching native macOS labels
bg             light: #FFFFFF   dark: #1C1C1E
bg-sidebar     light: vibrancy  dark: #232326
bg-elevated    light: #F7F7F8   dark: #2A2A2D
border         light: #E5E5EA   dark: #38383B
text           light: #1D1D1F   dark: #F2F2F7
text-muted     light: #6E6E73   dark: #98989D
danger         #E5484D
warning        #F5A524
success        #30A46C
mono-font      "SF Mono", "Menlo", monospace   (passwords, TOTP, generator)
radius         8 px panels, 6 px inputs/buttons
```

Follow system appearance by default; override in Settings (phase 5). Motion: 120–180 ms ease-out for panel transitions, none for list scrolling. Respect "Reduce motion". Primary buttons use `accent`; gpui-component's primary token must be set to it in both themes.

Popover menu rows (the Templates menu and similar): a fixed-width icon slot and a left-aligned label so text starts at the same x on every row; Enter and Space activate the focused row.

## 6. Accessibility and input

- Every interactive element reachable by Tab; focus ring visible.
- Dynamic type: respect the system text size step (phase 5).
- VoiceOver labels on icon-only buttons.
- No information conveyed by color alone (TOTP expiry also pulses the ring; strength meter has a label).

## 7. Phase-2 definition of done

Everything in §2.2–2.4 working against a real `.vault` file via `vault-sync` (watcher may be a no-op stub in phase 2), all actions in §4 bound, light and dark, no panics on empty vault, resizing, or rapid lock/unlock. Settings sheet may be a stub with the General tab only.

## 8. Out of scope for v1 UI

Multiple main windows, multiple simultaneously-open vaults, drag-and-drop between vaults, menu bar extra, Spotlight-style quick access window, browser integration, favicon fetching over the network (bundled icon pack only), markdown in notes.
