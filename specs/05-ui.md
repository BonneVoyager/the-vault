# 05 — `vault-app`: UI

Framework: `gpui` + `gpui-component`, versions pinned with `=`. Treat gpui as pre-1.0: wrap any API we touch in more than two places behind our own thin helper so an upstream rename is a one-file fix.

Reference look: 1Password 8 for macOS. Three columns, 13 pt system font, generous whitespace, subtle borders rather than heavy chrome, native-feeling vibrancy on the sidebar in both modes. (spec aligned to code 2026-11-19)

The app name is **Vault** in user-facing text, including menus, welcome and About screens. Use lowercase “vault” for an individual vault or vault file.

## 1. Window and layout

Single main window, 1100×720 default, min 820×520, state persisted (size, position, column widths) in `~/Library/Application Support/<bundle id>/window.json`. Title bar: hidden-title transparent style with traffic lights inset; the sidebar extends under it.

Columns are resizable via gpui-component's resizable panel; sidebar collapsible with `⌃⌘S` (View ▸ Hide Sidebar / Show Sidebar; 2026-10-31, Apple Passwords style). Collapsing removes the sidebar from the layout: the list keeps its width, its search row starts after the traffic lights (82 px inset), the sidebar toggle button stays at the left of the search row in both states, and the list shows the active filter ("All Items", "Favorites", "#tag") with its muted count above the rows only while collapsed. The state is remembered per app in settings.json, defaults to expanded, slides over 180 ms and is instant under Reduce Motion. While collapsed the window minimum width drops from 820 to 600 (via `vault-macos` `vault_macos::set_key_window_min_content_size`). The sidebar has no bottom bar and the window has no Settings or Lock button (owner decision 2026-10-31, as in 1Password and Apple Passwords): Settings is reached only through `⌘,` and the app menu; Lock only through `⌘L` and File ▸ Lock.

## 2. Screens / states

### 2.1 Launch → choose vault
First run, or no vault remembered: card with "Create new vault" / "Open existing vault…" / recent vaults list. Create flow: name, location (folder picker; shows a hint badge when the chosen folder is inside iCloud Drive or Dropbox), master password + confirm with live strength meter (same scale as the generator; owner decision 2026-11-17, option B: typed values are scored by zxcvbn through `generator::strength_bits`, capped at 64 bits, while the generator preview shows the exact entropy of its own pool and length; the shared buckets are Weak < 36, Fair < 50, Good < 56, Strong ≥ 56, bar full at 64 (Weak eased from 40 to 36 on 2026-11-17 so a 12-character random password, about 39.8 bits under zxcvbn, is normally not flagged; about 0.4 % of such passwords hit a chance pattern and score under 36, accepted); the generator's default length is 20 so a fresh random password also reads Strong once saved and re-scored by zxcvbn; a 4-word passphrase is 55.0 bits exact and reads Good in the generator (corrected 2026-11-21, bug hunt L2) while zxcvbn scores it 64 in a field) and a minimum of 50 bits per `generator::strength_bits` (Create stays disabled below it, inline message "Choose a stronger master password (at least 50 bits). Try a 4-word passphrase."), a "Suggest passphrase" link that fills both fields with a generated 4-word passphrase revealed once plus the note "Write it down. There is no recovery without it.", "Calibrating encryption for this Mac…" spinner (KDF calibrate), done. The same meter and minimum apply to Change master password. The minimum is enforced in the UI and the CLI (`--allow-weak` bypasses it there), not in `vault-core`.

### 2.2 Unlock
Centered card: render the existing 256 px icon at 128 × 128 pt, a small vault name 10 pt beneath it (lighter muted colour in dark mode), then the password field with placeholder "Enter master password", the "Unlock" button, Touch ID button if enrolled (triggers automatically on appear if enrolled and policy allows), and a readable muted, smaller, transparent secondary "Open another vault…" action with a subdued ⌘O hint. Use 20 pt between the icon/name group and the password field, and 12 pt between controls. A Passkey button appears if a passkey slot exists (post-phase-5, macOS 15). While a password or Touch ID unlock is in progress, hide the controls without changing the card size and show "Unlocking…". The icon's six-arm wheel starts fast, slows exponentially, then rotates steadily in an infinite loop. A compact 24-frame strip rendered from the original SVG covers one 60-degree spoke sector; frame zero is pixel-identical to the original icon. The strip stays mounted from the first frame and supplies idle, moving, and settling images, so there is no visual asset swap. On a failed unlock, the wheel eases forward to frame zero before resting. Reduce Motion keeps the icon still. A *failed* password or Touch ID unlock is held so "Unlocking…" stays up for at least 500 ms from the start of the unlock: a faster failure is held until then, a slower one shows as soon as it arrives. A *successful* unlock plays a finish of D = max(350 ms − elapsed, 200 ms) entirely on the unlock screen (owner decision 2026-11-06, serial: stop, flash, then the items): the wheel continues at its current speed, gets a short acceleration beat, decelerates and lands exactly on frame zero at 0.7·D; the keyhole flashes from the moment of success, concurrently with the stop: opacity full by 0.2·D, held to 0.6·D, gone by D with smoothstep edges (a keyhole-only raster with a wide saturated-blue halo and white core, drawn above the wheel, mounted from the first frame at opacity 0; the icon itself is unchanged); at D the unlock screen is unmounted and the main screen fades in alone over the window background (§2.3 crossfade); the unlock card and the items are never visible together. A Touch ID unlock at 150 ms shows the main screen fully at 500 ms; a 550 ms password unlock at 900 ms. Controls stay hidden and the card keeps its size through the finish. A lock or vault switch during the hold or the finish discards it. Reduce Motion stills the wheel and skips the finish but keeps the 500 ms minimum for both outcomes. Successful unlock focuses Search. After a master-password unlock of a version 1 file the app upgrades it to format 2 once (01 §9), saves, removes this Mac's Touch ID setup, and shows "Vault upgraded to format 2. Touch ID needs to be enabled again."; a Touch ID unlock never upgrades; a failure shows "Could not upgrade the vault format: <error>". Wrong password: the password input shakes subtly (only on a failed attempt; the card and other controls stay still), with no inline error message or reserved error space; no lockout counter in v1. `⌘O` switches vault. A vault whose format version or key slots are newer than this build (`UnsupportedVersion(v)` with `v` above `FORMAT_VERSION` on open, `NoUsableSlot` on unlock; version 0 or any other unsupported value is damage per 01 §1 and gets the integrity-check message on the choose screen instead, bug hunt 2026-11-21 L3) shows "This vault was created by a newer version of Vault." in place of the password field, Unlock and Touch ID buttons; the icon, vault name and "Open another vault…" stay, and neither the shake counter (`unlock_failures`) nor the Touch ID failure counter (04 §2) is incremented (implemented 2026-11-19; counters named 2026-11-21). The same card is raised while the vault is locked when vault-sync reports `SaveBlocked(NewerVersion)` for a newer file that arrived from another device (bug hunt 2026-11-21 N2), and by a Touch ID unlock that returns such an error (N3); it is cleared only by a successful unlock or by opening another vault.

### 2.3 Main (locked → unlocked transition is a 150 ms crossfade; switching the selected item is instant, no fade — owner decision 2026-10-31)

**Sidebar** (categories removed 2026-10-30): All Items, Favorites, Recently Deleted (2026-11-03: trash glyph, count of items in the trash, hidden when the count is 0), then the Tags section (collapsible, sorted alphabetically) — no Logins/Notes/Cards/Identities rows. Counts shown right-aligned in a muted color. Template tags carry an icon instead of the generic tag glyph: `#login` key, `#note` sticky note, `#card` credit card, `#identity` id card, `#server` server, `#license` file badge (2026-11-15); all other tags use the tag glyph. Settings opens a sheet (not a separate window) from `⌘,` or the app menu; there is no Settings button in the window (2026-10-31). **⌘1 … ⌘9** (owner decision 2026-11-07, replacing the earlier ⌘1/⌘2 list/detail focus keys, which are removed together with View ▸ Item List / Item Details) select the Nth sidebar row in display order: All Items, Favorites, Recently Deleted when it is shown, then the tags in their sidebar order, counted only while the Tags section is expanded; a number past the last row does nothing. The numbering follows the same order while the sidebar is collapsed. Keyboard movement between panes stays ⌘F (search), ↓/↑ and Enter (list → detail) and Tab.

**New item** (`⌘N`): a Templates menu — Login, Note, Card, Identity, Server, License — each a preset of fields plus one tag (`#login`, `#note`, `#card`, `#identity`, `#server`, `#license`) added automatically; the item has no category. More templates may be added later as field presets only. Server and License (owner decision 2026-11-15): Server = URL (url kind, label "URL"), Username (text), Password (password), Notes (notes), tag `#server`, Lucide `server` icon; License = Version (text), License key (`pin` kind since 2026-11-15; was `password` the same day), Website (url), tag `#license`, Lucide `file-badge` icon. Appended after Identity in menu order. Since 2026-11-15 the Card template's CVV and the License key are `pin` fields (new items only; existing items keep their stored kinds). Nothing else is special-cased: a Server shows its Username as the list subtitle like a Login; a License has no subtitle rule of its own. The detail header shows the title only (no kind label).

**Item list**: search field pinned at top and focused after unlocking; rows are 56 px: 32 px item icon (2026-10-31: a symbol or tinted letter chosen in edit mode, else a custom image stored as a hidden attachment, else the letter avatar from the title with a deterministic colour from the id hash; the bundled Simple Icons brand-logo step and its contrast rules were removed on 2026-11-16 by owner decision, and a stored icon of kind "logo" is treated as no icon), title (semibold), subtitle (username / card last-4 / first line of note; a field named "username" is only used when its kind is not sensitive, else the first email-kind field, before the card number; ⌘⇧U uses the same lookup), favorite star right-aligned, then a red "!" badge when the item has a weak (< 36 bits, 2026-11-17) or reused password (tooltip "Weak password" / "Reused password"). The audit runs once per vault change and is cached on the listing. Grouped by first letter when sorted A–Z; sort menu: Name, Recently Modified, Recently Created (by `created_at`, falling back to `modified_at` for items saved before it was recorded; added 2026-11-19). Empty state illustration + "Create your first item" when the vault is empty; "No results" with "Create '<query>'" when search is empty. Virtualized list. Double-clicking a row opens a movable read-only window pinned to that item's live details, with reveal and copy controls (owner-approved 2026-10-30). One window per item: a second double-click focuses the existing one. Windows are tracked in `AppState`, closed on lock, vault switch and item deletion, titled with the item's name, following renames live, "Untitled" when blank, trimmed to 120 characters (owner decision 2026-10-31, replacing the earlier fixed "Item details" title; the name is therefore visible in Mission Control and the Window menu while the window is open), and re-render once a second only while the item has a TOTP field.

Value areas in both the main detail view and item windows copy on click, or Enter/Space when focused, with the same pointer cursor, hover highlight and "Click to copy" tooltip. Masked passwords copy without being revealed; TOTP fields copy the current code. Item windows always copy from their pinned item, independently of the main selection.

Both hosts use the same read-mode detail renderer: header (title only), tags, warning cards, field fonts and colours, row spacing, TOTP countdown, password history, attachment row styling and modified footer. Copy feedback is the same transient pill in the window where copying occurred; it disappears after two seconds. Each item window keeps its own reveal and history-disclosure state. Editing controls remain in the main window.

**Detail**: read mode by default. Each field uses a horizontal row inspired by macOS Passwords (shared `detail::field_row`, also used by the item window and the backup viewer): the label on the left in the foreground colour, its value on the right in the muted foreground colour (masked dots, revealed secrets and notes included; links, the urgent TOTP colour and the copy/reveal icons keep their own), with 7 px top and bottom padding (owner decision 2026-10-31, for readability); the rule under the tags and the rows form one group, so the first row sits 7 px under the rule like every other row. Template fields are created with natural labels from a per-field table ("Username", "Password", "Website", "Notes", "Number", "Expiry", "CVV", "Name", "First name"); every app-side lookup by field name is case-insensitive so imported or CLI-created lowercase names behave the same; read-only labels render with the first character capitalised for display and stored names are never rewritten (2026-10-31). Each editor row is a field identified by its id (2026-10-31): a new row gets a fresh id, a rename edits the field in place, a removed row is tombstoned on Save, and two fields may share a name (no duplicate-name error). A field name may be left empty (placeholder "Name"; sections keep "Section name"); read mode then shows the value with an empty label column, and name lookups (subtitle, ⌘⇧U) ignore it. Copy, reveal and history are keyed by field id, so same-named fields reveal separately; history lines read "<Field> · replaced …" when the entry carries a field id. In edit mode, "Add field" pre-fills the kind's capitalised label ("Text", "URL", "One-time code", numbered on a case-insensitive collision) and a new field's name has its first character capitalised once when first typed; existing names, template fields and values are never changed. The detail fade-in is keyed on the selection only, so Edit and Cancel do not replay it. Every editor input (title, field name, field value, tag, generator "Use", QR scan, the pre-filled title of "Create ‹query›") is capped at 1 MiB of UTF-8 (cut on a character boundary; the input is reset to the kept text) with the muted inline message "Field limited to 1 MiB" under the row while input keeps hitting the limit; Save stays enabled (owner decision 2026-11-06, bug-hunt M1: the UX guard under vault-sync's 64 MiB save refusal; imports and remote merges are not capped here). Labels and values align in consistent columns: the label column is 26 % of the row (80–140 px), widened to fit the item's longest displayed label on one line (plus the icon slot when any field of the item has an icon) up to 40 % of the row, and labels longer than that wrap (owner decision 2026-11-20); the fit measures the read-mode label only, so in edit mode the name input (which also holds the grip, icon button and padding) may clip a long name; owner decision 2026-11-21: keep the read-mode column at the base width rather than widen it for the editor chrome (bug hunt 2026-11-21 N4, accepted); notes retain multiple lines, and the layout adapts to narrower detail panes. The same layout applies to item windows. Fields rendered per `FieldKind`:
- `text`, `email`, `url`: value + copy; `url` also gets "open in browser"
- `password`: dots, reveal toggle (`⌘⇧R`), copy (`⌘⇧C`), strength meter under it in edit mode, history disclosure (last 10 values with timestamps, each copyable)
- `pin` (owner decision 2026-11-15, for short secrets such as license keys, CVVs and device PINs): masked like `password`, same reveal and copy controls, mono font, secret pasteboard path, history disclosure; accepts any characters, not only digits; **no** strength meter, **no** Generate button, and never a Weak or Reused Password notice (it is outside the audit entirely, so it adds no list badge). `⌘⇧C`, `⌘⇧R` and the username/password lookups ignore it (first password field only). History entries sit under the row of the field they belong to, for password fields as well as PINs (owner decision 2026-11-17, bug-hunt note; a PIN disclosure reads "PIN history (n)"); entries of a removed field fall back to the first password row, else the first PIN row; "Clear history" clears that disclosure only; every disclosure on an item shares one open/closed state. Not offered by the CLI.
- `totp`: 6-digit code grouped as `482 193`, circular countdown ring, copy; auto-refresh every second; code turns amber under 5 s
- `notes`: multiline; since 2026-10-31 rendered as GitHub-flavoured Markdown in read mode (headings, emphasis, lists, tables, code, links) through one shared notes view in the detail column, item window and backup viewer. Single newlines stay line breaks (the source is given trailing-space hard breaks for rendering only, outside code blocks). Images show as their alt text and are never loaded; raw HTML shows as literal text; only http(s) links are clickable (the target shows on hover) and open through the same path as Open in browser; other schemes are plain text. Reference-style links (`[text][ref]`, `[text][]`, `[text]` with a `[ref]: url` definition at note start or after a blank line, heading, rule, code or another definition) behave like inline links: clickable only when the definition targets http(s), plain text otherwise; reference images never load; the rewrite is rendering-only, so select-all copy of the rendered note yields the inline form (2026-11-01). The editor and the Copy button keep the raw Markdown; the body is not click-to-copy; selection is on with source format. Notes use the foreground colour (the renderer cannot take the muted value colour).
- card number (an item-level rule, not a field kind; spec corrected 2026-11-19 to match the code): in an item carrying the `#card` tag (or the legacy `kind: card` extra) every non-section field named `number` (any case) is shown as `•••• •••• •••• 4242` (fixed dots when it has fewer than four characters) with a reveal toggle and "Copy card number"; the list subtitle shows `•••• 4242` when the item has no username. The card template stores Number as `text`, so the field itself is not sensitive and gets no strength or reuse audit.
- `date`, `month_year`: plain (`number` removed; an old `number` field renders as an unknown kind)
- unknown kind (from a newer version): masked like `password`, with reveal and copy; the field's name is its label and the original kind string is never displayed (spec aligned to code 2026-11-19)

**Password notices** (owner decision 2026-11-12, option A; replaces the item-level banners): under each `password` field whose value is weak or reused, one compact strip per issue inside the row, under the value line and above the row's rule, aligned with the value column: red "!" icon (a 12 px dot, vertically centred on the first text line at every text size, 2026-11-21), bold title "Weak Password" / "Reused Password", then the body on the same line, "This password is easy to guess and should be changed." / "Used by N other items. Reuse lets one leak unlock several accounts.", muted red background, small text, wrapping to two lines when narrow. A field that is both weak and reused shows two strips, weak first. Shown in read mode (detail column, item window and backup viewer through the shared `detail::field_row`) and in edit mode under the row's inputs, where it follows the typed value live (reuse is checked against saved items other than this one; the backup viewer checks against the backup's own items; trashed items show no strips). Not dismissable; it disappears when the value is fixed. No item-level banner remains; the strength threshold and reuse count are unchanged, but the audit is per field: `audit::Issues` maps item id → `Vec<FieldIssue { field: field id, issue }>` (every weak password field, every reused one, weak before reused within a field, fields in item order); the list badge shows the item's distinct issue kinds as before. Edit mode uses `audit::strength_bits` on the typed value and `audit::reuse_count(vault, value, exclude_item)` against saved items. Tags render as `#tag` chips under the title. Exactly one rule separates the last field from the footer, which reads "created <d> · modified <d> · <device>" when the item carries `created_at` (2026-10-31) and "modified <d> · <device>" otherwise; both dates use the relative form ("just now", "37m ago", "2h ago", "3d ago") within 30 days and the UTC date `YYYY-MM-DD` after that. **Section fields** (2026-10-31, `FieldKind::Section`): "Add field" offers Section; a new section row is named "Section" with the placeholder "Section name", the kind chip reads "Section", and it has no value input; Save writes an empty value. In read mode (detail column, item window, backup viewer via the shared `detail::section_row`) the heading is the name uppercased, bold, small and muted, spanning the row with no actions, click or pointer, 12 px extra space above unless it is the first field, and a 2 px rule in the border colour under it (ordinary rows use 1 px). A section's stored value is treated as empty and is never rendered, copied, revealed, searched or exported; every lookup by field name (subtitle, ⌘⇧U, card number, TOTP, copy-by-index) skips sections.

**Item icon picker** (2026-10-31): in edit mode the 44 px header tile opens a popover with an "Automatic" row (shows what automatic resolves to and clears the stored icon), a search field (owner decision 2026-11-16, see "Icon search" below), a grid of 40 symbols, 8 colour swatches, and "Drop or choose image…" (click opens a panel limited to PNG and JPEG files; the row and the header tile both accept a dropped file; PNG or JPEG, input ≤ 512 KB and ≤ 8192 px per side, downscaled to a 128 px PNG at drop time and stored through the attachment path as `icon { kind: "image", value: <attachment id> }`; the original is not kept; when rendering, a stored icon blob over 256 KB or 256 px per side, or one that fails to decode, is refused and the automatic icon shows instead; decoded tiles are cached per attachment id, at most 128, cleared on lock). Shape and colour are independent (2026-10-31): "Automatic" is the shape whenever no symbol is chosen and stays selected when a colour is picked; the colour row always shows the effective colour with the item's palette colour pre-selected (picking it again clears the override; no marker: the Automatic row's mini tile previews the effective shape and colour live) (the brand-logo colour-row rule was removed with the pack on 2026-11-16). Storage: Automatic + default → no icon; Automatic + colour → kind `letter` with the colour, which means "automatic shape with a colour override" (a tinted letter); symbol + default → `symbol` without colour; symbol + colour → `symbol` with colour. The icon blob never appears in any attachment list, count, window or the backup viewer; an older build shows it as an ordinary attachment. Choices save or cancel with the edit; arrows move, Enter picks, Esc closes the picker and returns focus to the title field. The same tile is used in the list row, the detail header, the item window and backup rows.

**Icon search** (owner decision 2026-11-16, revised the same day to Lucide only): a search field sits under the "Automatic" row, placeholder "Search icons", focused when the popover opens. With an empty query the grid shows the 40 curated symbols exactly as before. As the user types, the grid shows every icon of the full bundled Lucide catalog (about 1,830, embedded through the asset crate's all-icons bundle, about 0.75 MB raw) whose name contains the query, case-insensitive on the kebab-case name with hyphens treated as spaces, ordered: curated symbols first in their curated (themed) order, then name-prefix matches, then other matches, alphabetical within the two catalog groups, capped at 120 overall, no duplicates. A stored colour outside the 8-swatch palette (the CLI accepts any #RRGGBB) renders with the item's palette colour so the white glyph always clears 3:1. The grid is scrollable in both states, keeps its size, scrolls to follow the keyboard cursor and returns to the top on every query change. A chosen icon is stored as `icon { kind: "symbol", value: <Lucide identifier> }`, the same kind the 40 curated symbols use, so no format change; colour swatches apply to every icon. Results are computed once per query change, never per render. The field icon picker gets the same search (owner decision 2026-11-16): empty query shows the 40 curated symbols, a query searches the whole catalog, and `Field.icon` may hold any Lucide identifier. No matches: "No icons match" in the muted colour. The query is not persisted. A stored symbol name, for items and fields, resolves as the `IconName` identifier (`KeyRound`, exact case) or as the kebab-case Lucide name (`key-round`, any case; bug-hunt note 2026-11-17), so CLI-typed names render; the pickers always store the identifier.

**Attachments** section below the fields (v1.1): one row per file with a document icon, name, size, and state (present / "Not downloaded yet" / "Missing"). Actions: Preview (in-app only for images and UTF-8 text under 1 MB; images up to 20 MB and 50 megapixels, GIF canvas times frames; other kinds have no preview), "Save decrypted copy…" (NSSavePanel; confirm sheet "This writes an unencrypted copy to disk."), Remove (in edit mode only; no row menu) (spec aligned to code 2026-11-19). Add via "Add file…" (open panel) or by dropping files onto the detail column; files over 100 MB are refused with a toast. Adding and saving run as background tasks with the usual lock guard. Attachments are not backed up (owner decision); the backup viewer shows them as Missing.

Copy shows a transient "Copied — clears in 30 s" pill at the bottom of the detail column. Every toast pill (copy feedback, window toasts, the danger variant) is drawn in the opposite appearance's elevated palette so it stands out: in light mode the dark theme's fill, border and text; in dark mode the light theme's; the danger variant keeps its danger border and inverts the fill; its text contrast is at least 4.5:1 in both appearances: in light mode the fill is darkened to #18181B under #E5484D text, in dark mode the light fill stays and the text is the same hue at lower lightness, #DE2026 (owner decision 2026-11-21, option A; the dark-mode text shade is an orchestrator fallback because no lighter fill reaches 4.5:1, pinned by `danger_pill_text_contrast`).

**Field icons** (owner decision 2026-11-07): a field may carry an optional symbol chosen in the field icon picker (the 40 curated symbols, or any Lucide catalog icon via the picker search since 2026-11-16), stored as `Field.icon` (01 §4, 02). Read mode (shared `detail::field_row`, so the detail column, item windows and the backup viewer agree): when set, the symbol is drawn at 16 px in the muted foreground colour immediately left of the field name with the usual 8 px gap; when not set the row is exactly as before, no column is reserved, except that the label column's fit width counts the icon slot when any field of the item has an icon (2026-11-20). No colours, no custom images, no automatic letter; sections carry no icon. An unknown name (newer build) renders as no icon and is preserved on save. Edit mode: each field row (not section rows) gets a small ghost icon button left of the name input, showing the chosen symbol or a faint placeholder glyph when none; it opens a popover with a "No icon" row on top and the same symbol grid the item icon picker uses (shared code, not a copy), arrows move, Enter picks, Esc closes and returns focus to the name input. The choice is part of the edit buffer: saved on Save, dropped on Cancel; changing only the icon restamps the field (core). Not carried by CSV/1PUX/KDBX import or export; no CLI flag.

**Edit-mode field rows** (owner decision 2026-11-15, option A "mirror read mode", replacing the stacked name-over-value inputs): the rows form one group with the panel radius and a hairline rule between rows, exactly like read mode. Each row is horizontal: drag grip, icon ring, the name as a borderless input in the label column (same width as read mode's label column — the same fit width, measured from the edit buffer's names, so it grows while a name is typed (2026-11-20) — foreground colour, medium weight), the value as a borderless input filling the value column (muted colour until focused, mono for password/PIN/TOTP, dots with the reveal eye for masked kinds), then at the trailing edge the kind chip, the ↑/↓ buttons (visible only while the pointer is over the row or while one of the two buttons itself has keyboard focus; never shown just because the row's name or value input is focused, and never on a row the pointer is not over after a move; they stay in the layout invisible otherwise so their space is reserved and Tab from the value input still reaches ↑) and the trash, always drawn. The item title input in edit mode uses the same text size as the read-mode title (2026-11-16). **Move flash** (owner decision 2026-11-16, option A): after a row is moved by ↑/↓ or dropped by drag, the row's background fills with the accent at 18 % alpha and fades to clear over 900 ms with an ease-out, one pulse, so the eye finds the row where it landed; keyboard moves (Space/Enter on a focused arrow) do not flash since focus follows the row. Under Reduce Motion the fill shows for 300 ms and clears without a fade. A second move during a flash restarts it on the new position. Focus draws the accent ring on the focused input only, never on the row. ## 3. State model

One `AppState` entity (gpui `Entity<AppState>`) owning:

```rust
pub struct AppState {
    pub vault: Option<SyncedVault>,          // None = no vault chosen
    pub locked: bool,
    pub selection: Option<Uuid>,
    pub filter: Filter,                       // All | Favorites | RecentlyDeleted | Tag(String)
    pub query: String,
    pub sort: Sort,
    pub mode: Mode,                           // View | Edit(EditBuffer) | New(Template, EditBuffer)
    pub toast: Option<Toast>,
    pub sync_status: SyncStatus,
    pub settings: Settings,
    pub last_activity: Instant,
}
```

Views subscribe to `AppState` and re-render on `notify()`. Derived data (`filtered_items: Vec<Uuid>`) is recomputed on `query`/`filter`/`sort`/vault change and cached in state, not recomputed per frame.

`EditBuffer` is a plain clone of the `Item` being edited; Save calls `vault.edit(|v| v.update(id, now, |it| *it = buffer))`. Core recomputes field timestamps by diff (see 02 §`update`).

Sync events arrive on a `crossbeam_channel` receiver polled from a gpui background task; each event mutates `AppState` on the main thread and `notify()`s. `Merged` while editing: keep the edit buffer, show a toast "Vault updated from another device"; if the merged item is the one being edited and a field the user has touched changed remotely, mark that field with a small badge "changed remotely — your edit will win on save".

Toasts without a window (2026-11-12): `show_toast` while no main window exists (background start, window closed) does not start the toast's clock; the toast is held (one slot, the newest ordinary toast replaces an older one, a danger toast is never replaced by an ordinary one) and shown with a full TTL when the next main window opens. The three-second expiry runs only while a window is up. Copy pills are never held (their countdown is the clipboard timer). Accepted residual: toasts set from background results without an app context (Touch ID, restore errors) are not held; they keep their clock and may be cleared on the first tick after a reopen.

Menus without a window (2026-11-12): the menu bar follows the state, not the window. An app-level observer rebuilds the menus (`refresh_menus`) whenever lock state, trash view, sort or sidebar visibility changes, so an auto-lock with the window closed removes Settings… at once instead of on the next window open (closes the known corner of 2026-11-07). The main window's own refresh stays and is idempotent.

Auto-lock: a 1 s timer checks `vault_macos::seconds_since_user_input()` and `last_activity`; on threshold → `lock()`. Lock = close the Settings sheet, any toast, and every backup-viewer window; save if dirty; `vault.lock()`; clear selection and edit buffer; clear clipboard if ours; switch to Unlock screen. Every trigger (⌘L, idle, screen lock, sleep, user switch, key mismatch, window close, quit) goes through the same `lock()`. A background task (QR scan, Touch ID, save) that completes after a lock discards its result silently. Every new window is excluded from screen capture (best effort, `04` §3b).

Follow system appearance by default; override in Settings (phase 5). Motion: 120–180 ms ease-out for panel transitions, none for list scrolling. Respect "Reduce motion". Primary buttons use `accent`; gpui-component's primary token must be set to it in both themes.

**Menu popovers** (owner decision 2026-11-07, consolidation): every menu-shaped popup in the main window (the ⌘N Templates menu, the list Sort menu, the editor Add field menu) is one shared `ui::menu_popover` on top of the state-driven `ui::popover`, not gpui-component's `PopupMenu`/`dropdown_menu` (which paints from library theme tokens our overrides do not reach and cannot be opened from app state). Panel: the library popover frame with 4 px padding, rows 28 px (scaled with text size), 1 px apart, sized to content like a native menu (owner decision 2026-11-07, after seeing the empty slot and filler): width = widest row, no fixed minimum, labels never truncated below their natural width up to a 320 px cap. Rows (`ui::menu_row`): an icon slot reserved only when at least one row of that menu carries an icon (then on every row, so labels start at the same x within a menu), left-aligned label, a check-mark column reserved only when the menu is checkable (Sort: the current order carries the mark, the other row keeps the column), 24 px between label and check column or 16 px trailing padding without one, optional muted shortcut hint, hover accent, pressed 16 % primary, focus ring. Keyboard: opened from app state (⌘N, the "Create ‹query›" link, Item ▸ New Item) or by Space/Enter on the trigger the first row is focused; opened by a mouse click on the trigger no row is until ↓; ↑/↓ move and stop at the ends; Enter and Space activate; Esc closes. Open state lives in `AppState` (`template_picker`, `sort_menu_open`, `add_field_menu_open`) and is cleared on lock and vault switch; Add field also on edit start, Save and Cancel. Settings ▸ General choice dropdowns stay on `ui::menu_item` by design (owner decision 2026-11-08: Settings is kept separate from the main-window menus).

**Sidebar vibrancy** (owner decision 2026-11-13, option A; extended to dark mode the same day, option A): the main window uses gpui's blurred window background (`WindowBackgroundAppearance::Blurred`) in both appearances, and the sidebar column paints its tint (`#F5F5F7` light, `#232326` dark) at 0.88 opacity (owner eye check 2026-11-13: 0.70 let too much through; one constant for both modes until an eye check says otherwise) instead of a solid fill, so the desktop and windows behind show through blurred and tinted, as the sidebar in Apple Passwords and Finder. Everything else stays opaque: the list and detail columns, the unlock screen, sheets, the backup viewer and item windows paint their own backgrounds, and the root no longer relies on a single opaque window fill where the sidebar is. The fill does not change with window activation (owner decision 2026-11-13, option A: an active/inactive switch between translucent and solid read as a flash, because the two looks differed by far more than Apple's material does). Switching appearance (system or in Settings) changes only the tint colour; the window stays blurred. The collapsed sidebar leaves no translucent area. gpui's blur view strips Apple's material tint, so the grey is ours; if the eye check finds it off next to Passwords, the tint or opacity is tuned before a native `NSVisualEffectView` (option B) is considered. Implementation notes (2026-11-13): the main window is opened blurred (the mode no longer depends on appearance); window activation changes nothing; gpui-component's `Root` paints the whole window with the theme background, so the main window's `Root` is created with a transparent fill (`ui::main_root`) while item windows and the backup viewer keep the plain opaque `Root`; during the unlock→main crossfade an opaque underlay sits under the fade in both modes (solid under list and detail, fading out under the sidebar at its current width, including mid-slide) so the blur never shows across the whole window; under Reduce Motion there is no crossfade and no underlay.

**Menu key equivalents** (2026-11-07): gpui gives each app-menu item the first key binding of its action as the NSMenu key equivalent regardless of the binding's key context, and AppKit routes a key equivalent to the menu before the focused view sees it. So a menu item whose action is bound only in a context (↓/↑ Next/Previous Item in `ItemList`, Esc Cancel Edit in `ItemDetail`) would fire from anywhere. Such menu entries use separate menu-only actions with no binding (`MenuNextItem`, `MenuPrevItem`, `MenuCancelEdit`) and show no shortcut; the context-scoped keys reach the keymap only. Rule for new menu items: an item whose shortcut is focus-scoped gets an unbound menu action. In the search field ↓/↑ move the caret; the list is entered with Enter (owner decision 2026-11-07: no Spotlight-style ↓ from search for now, eye checks passed with this behaviour).

## 6. Accessibility and input

- Every interactive element reachable by Tab; focus ring visible. The item list is one Tab stop (owner decision 2026-11-08, option A): Tab order in the main window is sidebar rows → search → list → detail; Tab lands on the list as a whole, the selected row takes the focused colour, ↓/↑ move the selection, Enter opens the detail column, Shift-Tab returns to search. Rows are never individual Tab stops. Full order: sidebar rows, sidebar toggle, search, list, detail column, then the list toolbar (Sort, generator, New) so every control stays reachable. When focus enters the list by any route (Tab, ⌘F ⏎, click) and rows are shown with no selection, the first row is selected; never while an edit is open.
- Dynamic type: respect the system text size step (phase 5).
- VoiceOver labels on icon-only buttons.
- No information conveyed by color alone (TOTP expiry also pulses the ring; strength meter has a label).

## 7. Phase-2 definition of done

Everything in §2.2–2.4 working against a real `.vault` file via `vault-sync` (watcher may be a no-op stub in phase 2), all actions in §4 bound, light and dark, no panics on empty vault, resizing, or rapid lock/unlock. Settings sheet may be a stub with the General tab only.

## 8. Out of scope for v1 UI

Multiple main windows, multiple simultaneously-open vaults, drag-and-drop between vaults, a menu bar extra beyond the §2.5 status item shown while the Dock icon is off (2026-11-08), Spotlight-style quick access window, browser integration, favicon fetching over the network (bundled icon pack only), Markdown editing preview, Markdown images and raw HTML in notes.
